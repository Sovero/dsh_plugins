# dsh-client-voice-eternia — «Голос Этернии»

Голосовой ввод «Голос Этернии» для DeepSeek Harness: две кнопки на панели ввода — микрофон для диктовки и кнопка разговора для беседы голосом, русское
распознавание речи, вставка текста в позицию каретки.

## Зачем свой плагин

В DSH уже есть экспериментальный голосовой плагин. Отличия этого:

| | этот плагин | официальный (experimental) |
|---|---|---|
| Русская речь | **да** — через облачное распознавание | локальный SenseVoice русского не знает |
| Куда попадает текст | в позицию каретки, не затирая ссылки-чипы `@файл` | в конец черновика |
| Где ключ API | только на хосте | — |

Локальный движок DSH (SenseVoice) объявляет языки `auto, zh, en, yue, ja, ko` —
русского среди них нет. Поэтому распознавание идёт через облако, а ключ живёт на
хосте и в браузер не попадает.

## Установка

Пакет уже слинкован с профилем `web`. Если нужно поставить заново:

```powershell
cd "$env:APPDATA\dsh-desktop\harness\profiles\web"
pnpm add "link:C:/Projects/Python/dsh/dsh-client-voice-eternia"
```

Затем добавьте запись в `dsh.profile.bundles` файла `package.json` профиля и
строку в `cordis.patch.yml`:

```yaml
- insert:
    - id: dsh-client-voice-eternia
      name: dsh-client-voice-eternia
```

После правок **host-половины** нужен перезапуск DSH: загрузчик перечитывает
патч на лету, но уже импортированный модуль Node сменить нельзя. Удобный способ —
запустить `voice-eternia-restart-and-verify.cmd` из корня репозитория.

После правок **клиентской половины** достаточно `npm run build` и обновления
страницы (`Ctrl+R`).

## Настройки плагина

Все параметры задаются в карточке плагина (Настройки → Плагины → Голосовой ввод).
Объявлены схемой `Config` в `src/index.js` через `@deepseek-ai/schemastery` —
именно её рантайм превращает в форму, а `apply(ctx, options, config)` получает
значения третьим аргументом.

| Группа | Поле | Смысл |
|---|---|---|
| `asr` | `provider` | Провайдер: имя записи в `.credentials.yaml` |
| | `model` | Модель распознавания, должна принимать аудио |
| | `baseUrl` | Адрес API для OpenAI-совместимых сервисов, пусто — по умолчанию |
| | `language` | Подсказка языка речи для модели |
| `polish` | `enabled` | Включить полировку распознанного текста |
| | `model` | Модель редактора (обычная чат-модель) |
| | `prompt` | Инструкция редактору; пусто — встроенная |
| | `temperature` | 0 — предсказуемый текст, выше — свободнее правка |
| `recording` | `device` | Микрофон; пусто — первое входное устройство |
| | `maxSeconds` | Предел одной записи |
| | `inputGain` | Усиление входа; полезно тихим микрофонам |
| | `noiseSuppress` | Убрать низкочастотный гул |
| `insert` | `mode` | `cursor` — в позицию каретки, `captured` — в начало строки, `replace` — заменить черновик |
| | `preserveChips` | Не трогать @чипы файлов |
| `ui` | `showBrowserFallback` | Показывать кнопку браузера при отказе записи |
| | `confirmOnInsert` | Показывать карточку результата перед вставкой |

Настройки из карточки имеют приоритет над файлом `voice-eternia.json`. Файл не
удалён: в нём остались старые плоские настройки, и они читаются, если карточку
ещё не открывали. Значение неверного типа отбрасывается молча: с ошибочной
настройкой лучше поведение по умолчанию, чем падение на ровном месте.

## ⚠️ Микрофон и оболочка Electron

**Микрофон в окне DSH Desktop работает.** Запись ведёт хост, а не страница.

Наивно это выглядит невозможным: в обработчике разрешений Electron белый список
из двух пунктов,

```js
function canGrantWindowPermission(permission, requestingUrl, isMainFrame) {
  return (permission === "clipboard-sanitized-write" || permission === "notifications")
    && isMainFrame && isHarnessUrl(requestingUrl);
}
```

и разрешения `media` там нет, поэтому `getUserMedia` отказывает **молча, без
системного диалога**. Это чужая строка в подписанном `app.asar`: правка требует
прав администратора, ломает подпись и сносится при обновлении.

Но белый список относится к **окну**, а не к процессу. Хост — обычный Node, а
микрофон в Windows пишет любой программе, которой позволили. Поэтому запись
делает `ffmpeg`, запущенный хостом (`src/capture.js`), и страница в процессе
не участвует: кнопка диктовки просто спрашивает хост «начать» и «остановить».

Отсюда три требования, которые важно понимать:

- **`ffmpeg` должен быть в PATH.** Ставится один раз
  (`winget install ffmpeg`). Без него плагин скажет об этом прямо, а не
  промолчит.
- **Формат — сырой PCM через пайп.** Проверено: если просить ffmpeg писать WAV
  прямо в файл, он копит данные до конца записи, и файл остаётся нулевым все
  две минуты. С выводом в stdout и флагами `-avioflags direct -fflags nobuffer`
  поток идёт в реальном времени, а WAV-заголовок добавляется уже при остановке.
- **Индикатор уровня настоящий.** Он считается по сэмплам, пришедшим от
  микрофона, а не оценивается по времени.

Браузер при этом остаётся рабочим запасным путём: если `ffmpeg` не установлен и
запись на хосте невозможна, плагин покажет адрес того же интерфейса в браузере,
где `127.0.0.1` считается доверенным источником и микрофон работает штатно.
Показывается он только если это включено в настройках (`ui.showBrowserFallback`),
по умолчанию выключено — лишняя строка в полоске отказа только мешает.

### ⚠️ Ссылка обязана быть с токеном

Голый адрес вида `http://127.0.0.1:58046` браузеру **не годится**: `dsh web`
закрывает интерфейс подписью и отвечает

```
401 dsh web authentication required; reopen the URL printed by dsh web.
```

Поэтому `/env` отдаёт адрес, подписанный сервисом `connection`:

```js
connection.authenticatedUrl('http://127.0.0.1:58046')
// → 'http://127.0.0.1:58046?token=<токен запуска процесса>'
```

Сервис `connection` **не входит в `inject`** — он необязателен, и его
отсутствие не должно ронять плагин. Он читается императивно на каждый запрос
(`ctx.get('connection')`), потому что появиться может позже `apply`. Если
сервиса нет или он бросает, `webUrl` приходит пустым, и клиент **прячет**
кнопку: ссылка с заведомо мёртвым адресом хуже её отсутствия.

> Токен запуска — локальный, живёт только в памяти процесса и служит тем же
> целям, что и строка `dsh web: …`, которую `dsh web` печатает в консоль.

> **Почему нельзя «просто сделать плагин, который работает в приложении».**
> Блокировка стоит в оболочке, а не в плагине. Тот же `getUserMedia` вызывают и
> официальный `@deepseek-ai/dsh-experimental-client-ui-voice-input`, и сторонний
> `@goodandready/dsh-voice` — оба упираются в этот же белый список. Через
> плагин, живущий внутри харнесса, разрешение `media` получить нельзя; обойти
> это можно только правкой оболочки вне `app.asar`, и тогда патч придётся
> повторять после каждого обновления DSH.

## Как пользоваться

Управляет всем **сам микрофон**: он же переключатель. Других кнопок в панели
нет — их удаление было решением человека, а не украшением.

1. Нажмите микрофон на панели ввода.
2. Над полем появится полоска: пульсирующая точка, надпись и индикатор уровня.
   Никаких кнопок.
3. Говорите. Второе нажатие на микрофон останавливает запись.
4. Текст вставится в поле ввода **в то место, где стоял курсор**.

Если за время записи вы что-то напечатали, вставка не выполнится (чтобы не
затереть набранное). Тогда полоска покажет распознанный текст целиком — клик по
нему копирует текст в буфер, второе нажатие на микрофон закрывает полоску.

При ошибке полоска показывает причину и подсказку, как её закрыть: тем же
нажатием на микрофон.

## Настройки

Живут в карточке плагина (Настройки → Плагины → Голосовой ввод). Подробности и
состав групп — в разделе «Настройки плагина» выше.

Для совместимости прежних установок настройки дополнительно хранятся в
`$DSH_HOME/voice-eternia.json`; карточка имеет приоритет, файл используется,
только если карточку ещё не открывали.

| Поле | По умолчанию | Значение |
|---|---|---|
| `asrProvider` | `or` | провайдер распознавания (OpenRouter) |
| `asrModel` | `google/gemini-3.5-flash` | аудио-модель |
| `language` | `ru` | язык распознавания |
| `polish` | `false` | полировка текста (в разработке) |
| `polishModel` | `google/gemini-3.5-flash` | модель полировки |
| `polishPrompt` | `""` | свой промпт редактора |

Ключ берётся из `$DSH_HOME/.credentials.yaml` (`OR_API_KEY`). В браузер уходит
только распознанный текст — сам ключ остаётся на хосте.

## Маршруты

Все под префиксом `/voice-eternia`, доступны только с loopback:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/record/devices` | программа записи и список микрофонов |
| `POST` | `/record/start` | начать запись → `{ device, maxSeconds }` |
| `GET` | `/record/status` | `{ recording, level, seconds }` для индикатора |
| `POST` | `/record/stop` | остановить → `{ audioBase64, bytes, tookMs }` |
| `POST` | `/record/cancel` | бросить запись, ничего не возвращая |
| `GET` | `/env` | адрес того же GUI для браузера (`webUrl`, `port`) |
| `POST` | `/transcribe` | `{ audioBase64 }` → `{ ok, text, empty, tookMs }` |
| `POST` | `/polish` | `{ text }` → `{ ok, text, polished }` |
| `GET` | `/config` | текущие настройки и признак наличия ключа |
| `PUT` | `/config` | сохранить настройки |

## Разработка

```bash
npm run build   # сборка самодостаточного клиентского бандла + копия host-половины
npm test        # 27 тестов: бандл, WAV-энкодер, ключи, настройки, маршруты
npm run check   # build + test
```

Структура:

```
src/index.js                 host-половина: маршруты, ключи, опрос ASR, адрес браузера
src/client/index.js          регистрация кнопки в слоте, жизненный цикл
src/client/dictate.js        кнопка микрофона и машина состояний диктовки
src/client/talkButton.js     кнопка разговора
src/client/talk.js           разговор: слушание, отправка, озвучка
src/client/echo.js           наблюдатель за ответом агента
src/vad.js                   нарезка речи на фразы
src/speech.js                синтез речи (SAPI)
src/client/recorder.js       захват, ресемпл в 16 кГц mono, WAV, классификация отказов
src/client/api.js            вызовы host-маршрутов
src/client/theme.css.js      стили на токенах темы
scripts/build.mjs            склейка бандла без внешних зависимостей
```

Host-половина объявляет свои сервисы через `export const inject = ['webServer']`.
Это **имена сервисов**, а не пакетов: без объявления загрузчик вызвал бы `apply`
до готовности `webServer`, и маршруты молча не поднялись бы. Имена пакетов
живут отдельно — в `package.json` → `dsh.client.inject` (для браузерной
половины) и в `dsh.plugin.json` → `client.inject`.

Клиентская половина исполняется в браузере как самодостаточный модуль: без
`import`, без JSX, только `React.createElement`. UI-код обязан снимать за собой
всё — `ctx.effect` возвращает уборщик, иначе после перезагрузки плагина
останется горящий микрофон.

### ⚠️ React берётся только через `require`

В области видимости фабрики **нет** свободной переменной `React`. Рантайм
вызывает `factory(require)` — одним аргументом, — а React лежит в seed-таблице
модулей, то есть доступен исключительно так:

```js
var React = require('react');
```

Обращение к свободной `React` бросает `ReferenceError` при **первом же
рендере**. Симптом обманчив: плагин числится подключённым, ячейка слота
зарегистрирована и видна в реестре, но помечена как отстранённая
(`active: false`), а в логе хоста нет ни строки — кнопки просто нет.

Поэтому сборщик обязан начинать фабрику с `var React = require('react');`, и
тест пакета проверяет именно это: `materialize()` падает на старом бандле и
проходит на новом.

## Языки интерфейса

Плагин двуязычный: **русский** (по умолчанию) и **английский**. Китайский
добавлен обязательно: `zh` — встроенная локаль DSH, и без словаря весь
интерфейс при китайском языке показался бы набором ключей.

Всё живёт в одном пространстве имён `voice-eternia`
(`src/client/locales.js`):

```js
ctx.locale.register('voice-eternia', 'ru', ru)
ctx.locale.register('voice-eternia', 'en', en)
ctx.locale.register('voice-eternia', 'zh', zh)
```

Разметка берёт текст через `t`, который рантайм передаёт компоненту сам — за
это отвечает поле `locale` в регистрации ячейки:

```js
slots.register({ id: SLOT_ID, label: (t) => t('dictate'), locale: NAMESPACE }, DictateButton)
```

Три вещи, которые здесь легко сломать, и все три закрыты тестами:

- **Паритет ключей.** Сравнение наборов ключей русского, английского и
  китайского словарей. Забытый перевод ломает сборку, а не всплывает сырым
  ключом в интерфейсе.
- **Паритет плейсхолдеров.** Сравнение наборов `{message}` — забытый
  плейсхолдер дал бы текст без причины отказа, и сравнение ключей его бы не
  поймало.
- **Отсутствие русских строк в разметке.** Любое `setMessage('…')` мимо `t()`
  осталось бы русским при любом языке.

Русского нет среди встроенных локалей DSH — там только `zh` и `en`, — поэтому
язык добавляется отдельно, с откатом на `en`. Если язык уже занят (например,
его регистрирует пакет `dsh-client-locale-ru`), `addLanguage` бросил бы
исключение на занятом id — поэтому сначала читается каталог, и язык добавляется
только когда его там действительно нет. Иначе словари плагина не
зарегистрировались бы вовсе, а интерфейс показал бы сырые ключи.
