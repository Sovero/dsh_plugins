# Покров Ульгарда

Тема «Покров Ульгарда» для [DSH Desktop](https://www.deepseek.com/harness/) в
стиле тёмного фэнтези: ночь над мёртвым городом, пепел на ветру и фонарь,
который несёт искатель.

![Тёмная схема](preview-dark.png)

## Что на экране

Ночь Ульгарда лежит под всем интерфейсом, а панели становятся стеклом, сквозь
которое она видна.

| Слой | Что делает |
| --- | --- |
| **Небо** | От черноты зенита к тёплому свечению у горизонта: за холмом что-то горит |
| **Луна за покровом** | Диск в ореоле, дыхание света одиннадцатисекундным циклом |
| **Перистые полосы** | Тонкие тучи в левой части неба: гасят свет, не споря с луной |
| **Башни в три плана** | Дальние бледные и без окон, средние — с тёплыми окнами, ближние тёмные |
| **Врата** | Стрельчатая арка с обломанной правой опорой: вход в город, а не ещё одна башня |
| **Мгла** | Три ленты на разной глубине, идут в разные стороны и с разной скоростью |
| **Вороны** | Семь силуэтов, взмах крыла и скольжение через всё небо |
| **Пепел** | Медленно поднимается и гаснет; попав в свет фонаря, разгорается |
| **Земля** | Тёмная у нижнего края, с трещинами, расходящимися от врат |

## Фонарь

Главное отличие темы от статичного фона — **живой фонарь искателя**.

- Свет идёт за курсором и разгоняет тьму вокруг себя.
- Свет рисуется аддитивно (`lighter`), поэтому наложение пятен только ярче, а
  фонарь не оставляет грязных стыков.
- **Пепел, попав в пятно света, разгорается и льнёт к фонарю** — ровно то, ради
  чего тема и затевалась.
- Курсор ушёл из окна — фонарь гаснет плавно, а не рывком.
- Края экрана тонут в темноте: яркость тьмы по краям регулируется ползунком
  «Сумрак».

## Настройки

Тема добавляет **свою панель в левой колонке** — пункт с иконой арки и луны.
Там помещаются пояснения, образец палитры и кнопка возврата умолчаний.

| Настройка | Что меняет |
| --- | --- |
| **Тема включена** | Выключенная — возвращает фон оболочке |
| **Плотность** | Сколько башен, воронов и пепла на сцене (0.2–2) |
| **Сумрак** | Насколько глубоко тонут края экрана (0–1) |
| **Свет** | Радиус и яркость фонаря (0–1) |

Короткая строка-переключатель дублируется в **Настройки → Общие**: тема — это
предпочтение, и её ищут и там. Обе половины читают одно состояние, поэтому
расхождению взяться неоткуда.

Настройки хранятся в `localStorage` под ключом `dsh-veil-of-ulgard.prefs`.

## Языки

Интерфейс темы двуязычный: **русский** и **английский**. Язык следует за языком
DSH — отдельной настройки нет, и переключать его внутри темы нечего.

| Что переводится | Откуда берётся текст |
| --- | --- |
| Подпись пункта левой панели | Словарь темы через сервис локализации |
| Заголовки карточек, подписи настроек, пояснения | Словарь темы через сервис локализации |
| Названия образцов палитры | Словарь темы через сервис локализации |

Как это устроено:

- Словари обеих локалей регистрируются **одним вызовом**
  (`locale.register(ns, { en, ru })`), поэтому баланс набора ключей проверяется в
  одном месте. Ключ, забытый в одном языке, всплыл бы в интерфейсе голым именем
  (`page.title`) — ровно это ловит `tools/smoke.mjs`.
- Подписи слотов — **функции**, а не строки: владелец слота перечитывает thunk на
  каждой проекции, поэтому смена языка обновляет подпись без перерегистрации.
- Текст внутри панели подписан на смену языка (`locale.subscribe`) и перерисовывается
  сам: React не знает о смене словаря, и без подписки панель осталась бы на прежнем
  языке до перезагрузки.
- Если сервиса локализации нет, переводчик падает на язык браузера и словари темы —
  плагин читается и в урезанной сборке.

Строки темы лежат в `lib/client.js` рядом с кодом: у плагина нет сборочного шага,
и выносить словари в отдельные файлы значило бы собирать их вручную.

## Схемы

Тема несёт **обе схемы** и следует переключателю «Светлая/Тёмная/Системная»:

| | Тёмная | Светлая |
| --- | --- | --- |
| Что это | Ночь Ульгарда | Серое утро, покров истончился |
| Небо | Чернота с тёплым свечением | Пепельно-серое, тёплое у земли |
| Звёзды | Есть, тускнеют к горизонту | Нет |
| Башни | Почти чёрные силуэты | Серый камень с тёплыми окнами |
| Стекло панелей | `rgba(5,7,12,0.50)` | `rgba(222,214,196,0.52)` |

## Установка

Из этого репозитория:

```bash
dsh plugin --profile web add github:Sovero/dsh_plugins#path:dsh-veil-of-ulgard
```

Из локального пути (при разработке):

```bash
dsh plugin --profile web add /absolute/path/to/dsh-veil-of-ulgard
```

Пакет несёт конфигурацию bundle, поэтому при установке плагин сам попадает в
`dsh.profile.bundles` профиля. После установки перезапустите DSH Desktop: хост
собирает конфигурацию профиля при старте.

Удаление:

```bash
dsh plugin --profile web remove dsh-veil-of-ulgard
```

## Разработка

Проверка без браузера — подставляет заглушки окружения и выполняет код как есть:

```bash
node tools/smoke.mjs lib/client.js scene.svg
DSH_VEIL_SCHEME=light node tools/smoke.mjs lib/client.js scene-light.svg
```

Дым ловит ровно те поломки, из-за которых фон молча не рисуется: бандл не
зарегистрировался, слой не создан, сцена не является цельным SVG, у `xlink:` нет
объявления `xmlns:xlink`, слой стекла без пары светлая/тёмная, схемы совпали,
живой холст фонаря не создан.

## Технические решения

Они записаны здесь, потому что каждое стоило отладки.

- **Слой, а не фон документа.** Оболочка кладёт непрозрачный фон на `#root`, и
  картинка на `html, body` оказывается за ним — плагин работает, а ночи не
  видно. Слой с `z-index: -1` внутри изолированного контекста `body` встаёт между
  фоном страницы и содержимым приложения.
- **Прозрачность `#root` задаёт плагин.** Пока её задавала тема оболочки, ночь
  была видна; обновление оболочки сделало `#root` непрозрачным — и ночь пропала
  при живом плагине. `!important` перебивает любой неважный стиль оболочки.
- **Снимается только `background-color`.** Не `background` целиком: иначе
  пропали бы стеклянные градиенты панелей, ради которых тема и затевалась.
- **Слой стекла накладывается один раз.** `overrideTokens` сам публикует
  `theme/change`, слушатель звал бы его снова, и стекло уходило в бесконечную
  рекурсию (`RangeError: Maximum call stack size exceeded`). Работает форма слоя:
  каждому токену заданы обе схемы, и тема выбирает нужную сама.
- **`xmlns:xlink` объявляется обязательно.** Сцена едет в data-URL и разбирается
  как XML, где неизвестный префикс — фатальная ошибка. Без объявления весь
  документ не отрисуется целиком.
- **Слоты ищет собственный эффект, а не `apply`.** `ctx.get("slots")` в `apply`
  делал весь плагин реактивным к появлению сервиса — и отсюда «ночь появилась, а
  потом исчезла»: контекст протухал, эффекты снимались, `apply` вызывался заново.
- **`exports.inject = ['theme', 'slots', 'timer']`.** Fiber ждёт появления
  сервисов, и только после этого `ctx.get` отдаёт живой сервис. Без `timer`
  `ctx.timeout` бросает «cannot get property "timer" without inject» прямо внутри
  рассылки `theme/change` и обрывает её до подписчика макета.
- **Хостовой половине запрещено обращаться к сервисам.** Исключение из `apply`
  уносит волокно вместе с браузерной половиной — тема исчезает целиком, а в
  журнале видна одна строка вендора. Полезнее молчащий плагин.
