Корень проекта — ближайший предок с `.git`; без него берётся текущая папка.
Проверено: умение «Карта ветров» (`graphflow`) лежит на причале 400 и светится в каталоге борта —
значит причал рабочий и читается диспетчерской.

## 3. Формуляр карточки

```
<имя>/
└── SKILL.md
    ├── YAML-шапка: name, description (обязательно)
    └── Тело: наставление, < 500 строк
```

- `description` — главный механизм вызова: в нём **и что делает, и когда применять**.
  Пишем чуть настойчивее, иначе умение «недосрабатывает» и не вызывается.
- Тело пишем повелительным наклонением, объясняем **зачем**, а не только «делай».
- Большие справочники выносим в `references/`, скрипты — в `scripts/`, шаблоны — в `assets/`.
- Три слоя загрузки: шапка всегда → тело при вызове → вложения по требованию.

## 4. Запретная зона (Off-limits)

- **Не трогать** умения и пресеты, что поставляются с развёртыванием: `.agent-presets` рядом
  с конфигурацией дистрибутива и всё внутри `app.asar`. Обновление перезапишет, а порча
  пресета `cordis` отключит саму возможность править пресеты.
- **Не писать** в `node_modules`, `settings.yaml.imported`, `.credentials.yaml`, `.env`.
- **Не выдумывать** лицензии, контрольные суммы и статистику: берём только из наблюдения.
- **Не скачивать** внешний ресурс до проверки лицензии на странице источника.
- **Не переходить** к этапу N+1, пока этап N не прошёл гейт проверки качества.
- **Не создавать** грузы (плагины/бандлы) и не менять настройки борта ради этого задания.

## 6. Порядок выгрузки (по Плащу, без самодеятельности)

1. Стандарт оформления + культура (уже на борту — проверяем ссылкой).
2. `skill-catalog` — сначала знать, что уже есть.
3. `skill-lessons` — основной способ зафиксировать паттерны.
4. `skill-progress` — чтобы не терять прогресс между вылетами.
5. `skill-media` — статья-спутник, слайды, диаграммы.
6. `skill-license` — если есть внешние ресурсы.
7. `skill-qc` — измеримые пороги и гейты.

> «Сначала каталог, потом уроки, потом прогресс — и только тогда применение.»

## 7. Двойная проверка (обязательна)

- **Уровень 1:** у каждой задачи своя проверка (файл существует, шапка валидна, JSON разбирается,
  порог количественный, строка таблицы на месте).
- **Уровень 2:** весь результат сверяется со спецификацией и с чек-листом Плаща,
  затем расхождения превращаются в новые задачи (сходимость).

## 8. Источник истины

Порядок при споре: **текущая команда человека** → этот устав → спецификация → план → наблюдение
(файлы, вывод диспетчерской) → память. Память — историческая справка, не командная бумага.
