# 📋 Спецификация — «Применить плейбук Плаща для DeepSeek Harness»

## Цель

Перенести плейбук Чёрного Плаща с чужого борта на наш: установить шесть умений в ангар
DeepSeek Harness и **применить** их end-to-end к одному реальному репозиторию, чтобы на выходе
был не только комплект карточек, но и весь набор артефактов из чек-листа завершения.

## Критерий успеха

Все пункты чек-листа Плаща закрыты, шесть карточек валидны и читаемы диспетчерской,
артефакты применения лежат в одном предсказуемом месте, двойная проверка пройдена.

---

## Требования

| № | Требование |
|---|---|
| R1 | Созданы ровно шесть умений на причале 400: `skill-catalog`, `skill-lessons`, `skill-progress`, `skill-media`, `skill-license`, `skill-qc`. Каждое — папка `<dshHome>/skills/<имя>/SKILL.md`. |
| R2 | У каждой карточки валидная YAML-шапка с полями `name` и `description`. В `description` явно указано **что делает** и **когда вызывать**. |
| R3 | Тела адаптированы под наш борт: нет упоминаний `~/.hermes`, `skill_manage`, `localStorage`. Вместо них — таблица причалов, инструмент `skill` для загрузки, файл `progress.json`. |
| R4 | Два «уже существующих» стандарта не дублируются, а явно ссылаются: `skill-creator` и `agent-experience` (см. устав, §5). |
| R5 | Плейбук применён целиком: инжест → каталог → урок → прогресс → медиа → лицензии → проверки качества → журнал → передача смены. |
| R6 | Пороги качества количественные (не «хорошо», а «≤ 15 000 символов»), гейт между этапами зафиксирован, гард-хуки перечислены. |
| R7 | `LICENSES.csv` и `CREDITS.txt` созданы; внешние ресурсы не скачиваются без проверки лицензии на источнике. |
| R8 | `log.md` и `handoff.md` заполнены записями о применении. |
| R9 | Проверка в два уровня: по каждой задаче + сверка всего результата со спецификацией и чек-листом. |

## Что НЕ делаем (явно)

- Не публикуем умения в Базар у причала и не собираем груз (плагин/бандл).
- Не правим исходники DeepSeek Harness, не лезем в `app.asar`.
- Не меняем настройки борта, пресеты, `.credentials.yaml`, `.env`.
- Не переименовываем шесть умений: Плащ сослался на них по этим идентификаторам, они же
  упоминаются внутри самих карточек.
- Не подменяем живой выгрузкой данные примера про `ai.engineer/talks` (1 467 докладов,
  87 тем, 4 яруса) — в применяемом примере используем только то, что реально наблюдали.

## Вне объёма

- Живой обход внешнего сайта и скачивание его страницы.
- Создание седьмого умения «под ключ» сверх перечисленных шести.
- Оптимизация описаний через прогон оценок (это отдельный вылет, см. `skill-creator`).
- Перевод всего каталога умений борта на русский.

## Решения по неоднозначностям

Зафиксированы **до** сборки, чтобы не импровизировать в карточках. Помечены как принимаемые
по умолчанию — человек вправе заменить любое, и тогда карточки правятся точечно.

| № | Вопрос | Решение | Обоснование |
|---|---|---|---|
| D1 | Куда ставить? | Причал 400: `C:\Users\savchenkosv\.dsh\skills` | Проверено по архиву борта и по работающему `graphflow`; причал 500 занят внешним каталогом с замком `.skill-lock.json`. |
| D2 | Что считать «изучением сайта» для применения? | Реальный локальный репозиторий `C:\Projects\Python\dsh-pl` и сама система умений борта | Плейбук допускает «сайт/репозиторий». Так всё наблюдаемо, офлайн, без лицензионного риска. |
| D3 | Чем заменить `curl`/`web_extract`? | `read`, `glob`, `grep` и разведка через `pwsh`/`web_fetch` | Инструменты нашего борта equivalent по смыслу. |
| D4 | Чем заменить `C:/tmp/`? | Синтез-файл `applied/INGEST.md` в рабочей папке + исходные пути в нём | Артефакты должны быть доставлены человеку, а не растворены во временной папке. |
| D5 | Где живёт прогресс? | `applied/progress.json`, читается при каждом запуске умения | По плейбуку, этап 4; файл, а не Секретный отсек браузера. |
| D6 | Что делать с «уже есть»? | Сослаться на `skill-creator` + `agent-experience`, не создавать | Соответствует уставу §5 и приоритету №1 Плаща. |
| D7 | Язык артефактов | Русский; идентификаторы файлов и кода — как есть | Устав §1. |
| D8 | Диаграммы | Векторные SVG в `enrichment_diagrams/` | Плейбук: «векторные или сжатые», ≥ 1 штука. |
