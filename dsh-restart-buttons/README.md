# Кнопки перезагрузки для DSH Desktop

Две кнопки в подвале боковой панели DSH Web GUI: перезагрузить интерфейс или
полностью перезапустить DSH Desktop на Windows.

| Кнопка | Поведение |
| --- | --- |
| **Reload DSH** | `window.location.reload()` — перезагружает страницу и переподключает сессию. Применяет изменения клиентского плагина и пересобирает UI. Без участия хоста, без подтверждения, неразрушающе. |
| **Restart app** | Завершает и перезапускает DSH Desktop через долговечный отвязанный помощник. Двухшаговое подтверждение внутри кнопки: первый клик взводит кнопку на 5 секунд и меняет подпись, второй — стреляет. |

## Где живут

Обе кнопки регистрируются в корневом списке-слоте **`sidebar.footer.action`**
с id `dsh-restart-buttons` и `order: 100`, поэтому рисуются рядом с
штатным значком Cordis (`cordis-panel`, order 0) в подвале боковой панели —
прямо над блоком настроек с аккаунтом / строкой «⋯ Ещё».

Владелец слота передаёт пропсы `{ wide: boolean }`; когда боковая панель
сворачивается в 56-пиксельную рейку (`wide: false`), кнопки рисуют только
значки.

## Установка

Из этого репозитория (указывается подпуть к папке плагина):

```bash
dsh plugin --profile web add github:Sovero/dsh_plugins#path:dsh-restart-buttons
```

После установки перезапустите DSH Desktop: хост собирает конфигурацию профиля
при старте. Удаление — `dsh plugin --profile web remove dsh-restart-buttons`.

Если подпуть не поддерживается вашей версией DSH, распакуйте архив релиза и
установите из локального пути:

```bash
dsh plugin --profile web add /absolute/path/to/dsh-restart-buttons
```

## HTTP API

Оба маршрута отдаются веб-сервером DSH-хоста на порту GUI.

### `GET /dsh-restart-buttons/status`

Только чтение, зонд возможностей. Огорожен loopback, но не требует POST.

```json
{
  "ok": true,
  "plugin": "dsh-restart-buttons",
  "version": "1.0.0",
  "port": 19387,
  "electron": true,
  "appExecutable": "C:\\...\\DeepSeek Harness.exe",
  "parentPid": 19252,
  "restartEnabled": true
}
```

`403 {"ok": false, "error": "forbidden"}`, когда запрос не от доверенного
loopback того же origin.

### `POST /dsh-restart-buttons/restart`

Планирует полный перезапуск и отвечает **до** того, как тронут какой-либо
процесс.

| Статус | Тело | Значение |
| --- | --- | --- |
| 200 | `{ ok, id, logPath, delaySeconds }` | Запланировано. Воркер уже порождён. |
| 403 | `{ ok: false, error: "forbidden" }` | Не доверенный loopback same-origin POST. |
| 409 | `{ ok: false, error: "not-desktop" }` | Не под Electron-оболочкой. |
| 409 | `{ ok: false, error: "unsupported-platform" }` | Не Windows. |
| 500 | `{ ok: false, error: "schedule-failed" \| "internal" }` | Воркер не удалось породить. |

## Безопасность

Маршрут перезапуска может завершить приложение, поэтому он огорожен четырьмя
независимыми признаками до любого действия:

1. **Loopback-сокет** — RFC 5735 127/8, `::1` и IPv4-mapped `::ffff:127/8`.
   Адрес сокета авторитетен; `X-Forwarded-For` не доверяем.
2. **Loopback-заголовок `Host`** — `localhost`, `[::1]` или 127/8.
3. **`Sec-Fetch-Site` не `cross-site`.**
4. **`Origin`, если есть, должен точно совпадать с `Host`** — `localhost:19387`
   и `127.0.0.1:19387` — разные authority.

Поверх этого маршрут **только POST** (обычная навигация или `<img src>` до него
не дойдут) и отказывает 409 вне Electron-оболочки, так что простой `dsh web`
хост нельзя убить через него.

Браузерная половина дополнительно требует **второго клика в течение 5 секунд**
перед отправкой перезапуска.

## Как устроен перезапуск

`lib/restart.mjs` делит работу надвое, потому что процесс, который должен
выполнить перезапуск, — это сам перезапускаемый процесс:

- **Режим планирования** проверяет опции, пишет фазу `scheduled`, порождает
  отвязанного воркера с `stdio: 'ignore'` + `unref()`, дожидается только
  подтверждения порождения и сразу возвращается.
- **Режим воркера** спит задержку, проверяет, что целевой pid жив, запускает
  `taskkill /PID <pid> /F` — **никогда `/T`**, потому что воркер сам является
  потомком хост-процесса и древовидное уничтожение убило бы воркера, который
  должен перезапустить приложение, — ждёт освобождения порта, перезапускает
  исполняемое с удалённым из среды `ELECTRON_RUN_AS_NODE` (иначе приложение
  стартует как обычный Node, а не GUI) и опрашивает порт, пока тот не ответит.

`lib/restart-cli.mjs` выставляет планировщик для ручного запуска:

```
node lib/restart-cli.mjs --delay-seconds 45
node lib/restart-cli.mjs --help
```
